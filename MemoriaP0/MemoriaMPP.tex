double *d = (double *) malloc(((n*n-n)/2)*sizeof(int));

\begin{verbatim}
valgrind --tool=memcheck --track-origins=yes --leak-check=yes --log-file=valgrind.txt

Estas directivas permiten buscar fugas de memoria y desbordamientos, además de proporcionar información sobre la línea en la que se produce cada error. El primer error corresponde al fichero \texttt{io.c}, en la línea 14:

\begin{verbatim}
double *d = (double *) malloc(((n*n-n)/2)*sizeof(int));
\end{verbatim}

El problema que tenemos aquí es que se declara un array de tipo \texttt{double} y se reserva memoria utilizando el tamaño de un entero. Por lo tanto, la cantidad de memoria reservada no es la adecuada para los elementos que se almacenarán en el array. La solución es sencilla: cambiar \texttt{int} por \texttt{double}, que es el tipo que corresponde.

Para solucionarlo, únicamente tenemos que mover la liberación a una línea posterior, en la que ya no necesitemos utilizarla.

En la línea 46 de \texttt{io.c} nos salimos de la memoria al utilizar un menor o igual:

\begin{verbatim}
for(int i = 0; i < m; i++) { printf("%d ", solucion[i]); }
\end{verbatim}

Se soluciona quitando el igual para evitar salirnos de los límites del array.

\begin{verbatim}
==31682==  Uninitialised value was created by a heap allocation
==31682==    at 0x4846828: malloc (in /usr/libexec/valgrind/vgpreload_memcheck-amd64-linux.so)
==31682==    by 0x1098F5: aplicar_mh (mh.c:72)
==31682==    by 0x109339: main (main.c:48)
\end{verbatim}

En la línea 122 de \texttt{mh.c} se libera \texttt{poblacion}, pero \texttt{poblacion} contiene punteros a listas, por lo que no estamos liberando todo su contenido. Por este motivo aparecen numerosos errores relacionados con accesos a memoria no inicializada.

Se soluciona liberando todo el contenido antes de liberar \texttt{poblacion}:

\begin{verbatim}
for (int  i=0; i<tam_pob ; i++){
free(poblacion[i]->array_int);// segundo arreglo leak memoria
free(poblacion[i]); // primer arreglo leak memoria. El tercero esta en io.c free d
}
\end{verbatim}

Finalmente, se crea una variable \texttt{d} que nunca se libera. Buscamos el punto en el que deja de utilizarse y la liberamos mediante \texttt{free(d)} al final de \texttt{main}, junto con la liberación de \texttt{sol}.

==36402==
\end{verbatim}

Este último resultado nos confirma que se ha liberado toda la memoria correctamente y que no quedan fugas de memoria.
